\section{Git History}

Modern academic and industrial software engineering demands strict adherence to rigorous version control practices. In machine learning research, version control transcends traditional source code management; it is fundamental to \textbf{scientific reproducibility}, systematic ablation tracking, data pipeline traceability, and collaborative auditability. 

This chapter documents the complete version control strategy, repository architecture, chronological engineering milestones, and authenticated commit history for the \textbf{MedSpecialty AI} project repository hosted under Git version control.

\subsection{Version Control Strategy and Repository Architecture}

The project repository was managed using the distributed \textbf{Git} version control system, integrated with standard software development conventions.

\subsubsection{Branching Strategy and Workflow}
The repository adhered to a streamlined Trunk-Based Development workflow combined with targeted feature branches:
\begin{itemize}
    \item \textbf{\texttt{main} Branch}: The primary production branch containing verified, tested, and deployable code, serialized model weights, and peer-reviewed technical documentation. Every merge into \texttt{main} underwent validation for reproducibility and compilation integrity.
    \item \textbf{Exploratory / Feature Branches}: Ephemeral task-oriented branches utilized during exploratory data analysis, hyperparameter tuning experiments, LaTeX chapter drafting, and UI styling iterations.
\end{itemize}

\subsubsection{Commit Conventions and Semantic Versioning}
To maintain a clear and informative audit log, commit messages strictly followed the \textbf{Conventional Commits} standard, utilizing standardized semantic prefixes:
\begin{itemize}
    \item \texttt{feat}: Introduction of new functionality, such as baseline classifiers, Flask endpoints, or LaTeX chapter structures.
    \item \texttt{fix}: Resolution of bugs, layout overlaps, or mathematical discrepancies.
    \item \texttt{docs}: Updates to technical documentation, research paper reviews, project proposals, or presentation speaker notes.
    \item \texttt{refactor}: Code restructuring, vocabulary optimization, or layout enhancements without altering observable behavior.
    \item \texttt{chore}: Maintenance tasks, dependency updates, lock file removal, and artifact synchronization.
    \item \texttt{style}: Cosmetic and typography adjustments, color contrast fixes, and CSS styling enhancements.
\end{itemize}

\subsection{Repository Metrics and Code Quality Assurance}

To ensure long-term maintainability, the codebase was structured according to modern Python packaging and web development standards:
\begin{itemize}
    \item \textbf{Modularity}: Core training routines (\texttt{02\_train\_\allowbreak and\_\allowbreak balance\_\allowbreak models.py}) are decoupled from production inference services (\texttt{app.py}), ensuring that model updates do not disrupt production API routing.
    \item \textbf{Asset Organization}: All front-end assets are strictly segregated into dedicated directories:
    \begin{itemize}
        \item \texttt{static/css/}: Modular CSS stylesheet (\texttt{styles.css}) implementing custom clinical design tokens, responsive media queries, and flexbox layouts.
        \item \texttt{static/js/}: Asynchronous client-side logic (\texttt{app.js}) handling file drag-and-drop, real-time fetch requests, dynamic chart rendering, and DOM updates.
        \item \texttt{templates/}: Clean Jinja2 HTML5 template (\texttt{index.html}) containing semantic markup and accessible ARIA attributes.
    \end{itemize}
    \item \textbf{Data Security}: Confidential patient records and serialized binary files are protected from unintentional repository exposure via a structured \texttt{.gitignore} configuration.
\end{itemize}
